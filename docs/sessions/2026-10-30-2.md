# Session 2026-10-30 (2) — Phase 0 : xtool sur le serveur

- **Objectif et preuve** : installer xtool et le SDK iOS sur le serveur. Preuve : `xtool --help` et `xtool sdk` OK sur le serveur.
- **Fait** :
  - Evan a téléchargé `Xcode_27.2.xip` (Xcode 27.2 final, Swift 6.4), copié sur le serveur dans `~/hyphn/xtool/` en 1 min 9 s ; même taille et même SHA-256 des deux côtés.
  - xtool 1.24.0 en Docker (image officielle) ; **preuve 1** : `docker compose run --rm xtool --help` affiche les commandes.
  - **Preuve 2** : `xtool sdk install /work/Xcode_27.2.xip` → code 0 en 2 min 38 s ; `sdk status` = « Darwin SDK is installed » ; `swift sdk list` = `darwin` (iPhoneOS 27.2).
  - Place : `.xip` déplacé de C: vers `F:\Downloads` ; 19 images Docker orphelines (anciens builds `apphome`, `tv-accueil`) supprimées sur le serveur, aucun conteneur ni volume touché.
  - Commit `33ccf0e` (compose + docs).
- **Pas fait** : Apple ID secondaire et `xtool setup` (connexion) ; préparation de l'iPhone ; SideStore. Pas de push.
- **Décisions** : [[ADR-0011 xtool en Docker]] (accepté par Evan).
- **Problèmes rencontrés** :
  - L'URL de la doc d'installation notée dans les sources était fausse (`xtooldocs`) ; la bonne est `xtool.sh/documentation/xtool/installation-linux`.
  - Le journal de `sdk install` fait 2,4 Mo de barres de progression : lancer avec `| tail` ou filtrer.
- **Appris** :
  - `xtool sdk install <xip>` marche **sans** connexion Apple : l'Apple ID n'est utile que pour signer.
  - L'installation télécharge `OpenAppleMacros` sur internet.
  - SDK en mode `normal` ≈ 7 Go dans le volume ; il garde de quoi faire `xtool sdk update`.
  - usbmuxd 1.1.1 et fuse3 étaient déjà sur le serveur.
- **Non vérifié** : build et signature d'une app depuis le conteneur ; xtool avec l'anisette du serveur ; reprise du volume après un redémarrage du serveur.
