# Session 2026-10-30 (3) — Phase 0 : iPhone et SideStore

- **Objectif et preuve** : SideStore installé sur l'iPhone avec l'Apple ID secondaire. Preuve : SideStore connecté et « Refresh All » réussi avec LocalDevVPN connecté.
- **Fait** :
  - iPhone 16 Pro Max, iOS 27.0.1 : code de verrouillage vérifié, LocalDevVPN installé (App Store), mode développeur activé après la pose de SideStore (l'option est cachée avant).
  - PC : iTunes (Microsoft Store) pour le service Apple Mobile Device ; iloader **v2.4.1** installé en silencieux dans `F:\iloader` (`/S /D=F:\iloader`), SHA-256 du `.exe` identique à celui publié sur GitHub.
  - Apple ID secondaire créé par Evan ; connexion iloader réussie avec l'anisette `mac-ani.jkcoxson.com`.
  - iloader : « SideStore (Stable) » = SideStore **0.7.0-alpha** ; téléchargement, signature, installation et fichier de jumelage OK.
  - SideStore réglé sur l'anisette jkcoxson, connexion OK, **Refresh All réussi** (confirmé par Evan, sans capture).
- **Pas fait** : « Hello » xtool, raccourci quotidien, plan B AltServer. Pas de push.
- **Décisions** : [[ADR-0012 Anisette Mac publique]] (choisie par Evan).
- **Problèmes rencontrés** :
  - Timeout vers `192.168.1.63` (erreur 10060) : le partage de connexion de l'iPhone branché en USB crée la carte « Apple Mobile Device Ethernet » (métrique 25) qui passe avant le Wi-Fi (35). Corrigé en coupant le partage de connexion.
  - `Auth error -80045` avec l'anisette du serveur : Apple refuse depuis le 12/10/2026 une connexion dont l'anisette (Android) ne colle pas avec l'appareil annoncé ; iloader 2.4.1 annonce toujours un Mac (`Mac15,7`). Depuis le 22/10, -80046 refuse aussi le jeton Xcode à un appareil « Android ».
  - SideStore : même -80045 tant qu'il utilise l'anisette sur l'iPhone.
- **Appris** :
  - iloader : un serveur perso sans `http://` devient `https://` (lu dans `account.rs`).
  - SideStore 0.7.0 : la ligne **Anisette Servers** (Settings → ADVANCED SETTINGS) est cachée tant que **On-Device Anisette** (User Customizations → ANISETTE) est activé. Puis Anisette Client Configuration → Fetch → Save as Overrides → Save Overrides, et Reset adi.pb.
  - Le serveur anisette ne reçoit ni mot de passe ni code (SRP direct vers Apple) ; il voit l'IP et l'identifiant machine.
  - iOS n'a qu'un VPN actif à la fois : LocalDevVPN coupe WireGuard.
- **Non vérifié** : xtool sur le serveur avec l'anisette jkcoxson ; rafraîchissement sans câble à J+7 ; comportement si `mac-ani.jkcoxson.com` tombe (502 déjà signalé chez iloader).
